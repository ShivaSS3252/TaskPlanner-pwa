# TaskPlanner PWA

A production-ready, offline-first task management Progressive Web App built with React, Node.js, MongoDB, and Firebase — featuring AI-powered task breakdown, real-time sync, and push notifications.

---

## What Problem Does This Solve?

Most task managers break the moment you lose internet. You're on a train, in a basement, or dealing with a bad connection — and suddenly you can't add a task, mark something complete, or even load the app.

**TaskPlanner PWA solves this.** It works fully offline, queues every action you take, and syncs everything the moment you're back online — without you doing anything. It also solves the "I don't know how to break this big task down" problem with built-in Groq AI that splits any task into clear, actionable subtasks in seconds.

---

## Features

### Offline-First Architecture
- All tasks and categories are stored locally in **IndexedDB** — the app works with zero internet
- Every create, update, and delete made offline is **queued and synced** automatically when you reconnect
- Background Sync API ensures syncing happens even if you close the browser tab
- Visual indicators show which tasks are pending sync vs. already saved to the server

### AI-Powered Task Breakdown
- Click the **AI button** on any task to get 3–5 actionable subtasks generated by **Groq (Llama 3.3 70B)**
- Subtasks are specific, concise, and immediately actionable
- Add individual subtasks or all of them at once with one click

### Real-Time Multi-Device Sync
- Built with **Server-Sent Events (SSE)** — when you add a category on one device, it appears instantly on all others
- Automatic reconnect with heartbeat keeps the connection alive
- Live connection status indicator so you always know sync state

### Push Notifications
- Firebase Cloud Messaging (FCM) sends push notifications when categories are updated
- Works even when the app is closed (background service worker handles messages)
- One-click permission setup inside the app

### Full Task Management
- Create tasks with **priority levels** (Low / Medium / High) and **due dates**
- Organize tasks into color-coded **categories**
- Filter by category or search in real-time
- Soft delete preserves history and supports offline sync integrity

### Analytics Dashboard
- **Overview stats:** total tasks, completed count, completion rate, overdue count
- **7-day activity chart** — tasks created vs. completed by day
- **Priority distribution** pie chart
- **Category progress** bar chart showing top 6 categories and their completion rates

### PWA — Installable on Any Device
- Add to Home Screen on Android, iOS, Windows, and macOS
- Launches in **standalone mode** (no browser UI — feels like a native app)
- All static assets precached on install for instant load times
- Offline fallback page if everything fails

### Authentication
- **Google OAuth** via Firebase — one click to sign in
- All data is user-scoped — you only ever see your own tasks and categories
- JWT tokens verified on every API request

### User Interface
- **Dark / Light theme** toggle
- Two-column masonry layout for desktop
- Sticky header with search, theme toggle, notifications, and profile menu
- Toast notifications for actions (saved offline, synced, errors)
- Responsive design — works on mobile and desktop

## Getting Started

### Prerequisites

- Node.js 18+
- MongoDB (local or Atlas)
- Firebase project (Auth + Cloud Messaging enabled)
- Groq API key (free at console.groq.com)

### 1. Clone the repo

```bash
git clone https://github.com/YOUR_USERNAME/TaskPlanner-pwa.git
cd TaskPlanner-pwa
```

### 2. Setup the backend

```bash
cd backend
npm install
cp .env.example .env
# Fill in your values in .env
npm run dev
```

### 3. Setup the frontend

```bash
cd frontend
npm install
cp .env.example .env
# Fill in your values in .env
npm run dev
```

### 4. Firebase Setup

- Create a Firebase project at [console.firebase.google.com](https://console.firebase.google.com)
- Enable **Google Sign-In** under Authentication
- Enable **Cloud Messaging** for push notifications
- Download your **service account JSON** and place it at `backend/firebase-service-account.json`

## How the Offline Sync Works

1. User creates/edits/deletes a task while offline
2. Action is saved immediately to **IndexedDB** with a `pending` status
3. A sync operation is queued in the **Background Sync API** (`sync-tasks` tag)
4. When the device reconnects, the service worker fires the sync event
5. `sync.js` reads all pending operations from IndexedDB and replays them to the server
6. Successfully synced items are marked `synced`; failed items stay queued for retry

This means **you never lose data**, even if you close the tab or restart the device while offline.

---

## How the AI Breakdown Works

1. Click the ✦ button on any task
2. The task text is sent to **Groq (Llama 3.3 70B)** with a prompt that asks for 3–5 specific, actionable subtasks
3. The response is parsed and displayed in a panel below the task
4. Click individual subtasks to add them, or "Add All" to add everything at once
5. Added subtasks appear as new tasks in your list

## Service Worker Caching Strategy

| Content Type | Strategy | Details |
|---|---|---|
| JS / CSS / HTML | Cache First (Precache) | Cached on install, instant load |
| Images | Cache First | 50 entries max, 30-day TTL |
| Task API calls | Network First | Try server, fallback to 24h cache |
| User profile | Stale While Revalidate | Serve cache + fetch fresh |
| Navigation (offline) | Offline fallback | Serves offline.html |
